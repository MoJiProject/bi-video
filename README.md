bi-video
===

界面主题、图标、文案均为本项目自有设计与实现（主题色 `#0FA68E` 青玉 / `#FF8A4C` 蜜橙，
图标为自绘 SVG 后批量导出的 PNG），未使用任何第三方站点的品牌素材。

## 无后端离线预览

仅在前端开发模式（`cd static` 后执行 `npm run serve`）可用。在当前前端地址后加
`?preview=1`（例如 `http://localhost:8080/?preview=1`），即可用明确标注的示例账号查看页面。
右下角可切换首页、消息、投稿、稿件管理、创作数据、视频详情、个人空间和个人账户；
面板可收起，账户页内仍可切换资料、头像和背景，消息内仍可切换各个分类。

开启状态保存在独立的 `bi_video_offline_preview` 键，刷新及新标签页会延续预览。
真实账号的 token 和用户 ID 不会被替换或清除；点击“退出预览”，或访问 `/?preview=0`，
会重新加载并恢复原来的真实登录状态。生产模式始终禁用预览，即使 URL 或存储中有开关。

预览数据在前端请求适配器中提供，API 不发往后端；视频实时连接、私信 WebSocket
及观看历史的直接 `fetch` 上报也不会连接后端。预览不是实际登录，不修改服务端鉴权。
除当前页面的本地消息已读状态外，提交、上传和删除等写操作会明确提示未执行，不会假装保存成功。
视频展示原创几何示例封面和控制面板，没有附带真实视频或外部媒体，不支持实际播放。
此模式供检查布局、响应式和登录后内容展示，不代替真实接口、播放及持久化功能验收。

## 个人空间接口

`/home` 页面使用 `product-app`，请求统一通过 `services/http.js` 发送，登录凭证放在
`token` 请求头，不再使用旧版加密载荷或 `Authorization` 认证。
`/api/home/*` 提供投稿、动态、图文、收藏夹及收藏视频查询，分页返回
`records`、`total`；视频和动态分别使用 `VideoListItemVO`、`PostVO` 字段。
主页资料、签名和隐私设置使用 `/api/auth`，关注操作使用 `/api/user`，
关注及粉丝列表使用 `/api/home/relations`。
访问权限由后端根据登录身份判断，不使用前端传入的浏览者 ID 授权。

隐私设置支持收藏、关注列表、粉丝列表、点赞列表及生日；个人空间首页分区顺序可保存。
投稿支持搜索、排序、分页和最多 3 个代表作；关注及粉丝支持搜索、取消关注。
收藏夹支持管理、批量删除、复制、移动和清除失效内容，写操作由服务端校验收藏夹归属。
个人空间已移除合集入口与占位页面，旧 `homeMenu=4` 链接自动回到空间主页；
其他栏目编号保持不变。追剧原为本地演示，此处不将模拟数据包装成真实的持久化功能。

## Banner管理

后台列表入口为 `/systemManagement/banner`，支持新增、编辑、删除、排序和隐藏。
图片必填，支持JPG/PNG/GIF，最大10MB；内容选填，填写内容时链接必填。
链接支持HTTP/HTTPS或以 `/` 开头的站内路径。首页按排序升序、ID倒序最多展示6张，
每5秒自动轮播并支持手动切换，内容叠加在图片内部底部，有链接的图片可点击跳转。

本分支使用首页现有的首屏Banner区域，保留其尺寸和响应式占位，不引入旧分支510×370px的固定布局；
未配置展示项时保留现有首页。接口通过 `services/http.js` 和 `token` 请求头访问，
管理端身份以服务端登录用户为准，不接收客户端提供的管理员ID，写操作记录到 `operation_log`。
图片复用当前上传存储及 `/upload/` 静态资源服务。

已有 `product` 数据库执行 `sql/product/04_banner.sql`；新建数据库的 `01_schema.sql` 已包含该表。
不要对已有数据库重新执行全量建表脚本。

## 接口与上传部署

页面统一使用 `services/http.js` 和 `token` 请求头。历史及稍后观看使用
`/api/history/list`、`/api/watch-later/list`，游标为记录 ID，不是视频 ID；
动态使用 `/api/post`，资料及隐私使用 `/api/auth/profile`、`/api/auth/privacy`。

历史与稍后再看支持全部/今天/昨天/近一周及自定义日期筛选、标题或 UP 昵称搜索、
单条/批量删除和清空；历史按观看时间分组，稍后再看可切换最近/最早添加。
列表使用 `cursorId`、`cursorTime` 双游标；`startTime` 含起点，`endTime` 不含终点
（选择结束日期时前端传次日零点），稍后再看排序参数为 `order=newest|oldest`。
批量删除分别使用 `DELETE /api/history/batch`、`DELETE /api/watch-later/batch`，
JSON 为 `{ "videoIds": [1, 2] }`（单次最多 1000 条），用户身份仅由登录态决定。
历史记录开关读取 `/api/auth/me` 的 `recordHistory`，通过
`PUT /api/auth/privacy` 部分更新 `{ "recordHistory": false }`；关闭后观看上报不再写入历史，
重新开启不会清空原有记录。对应字段在 `sql/product/01_schema.sql` 的 `user_privacy` 中定义。

动态支持关注 UP 筛选、全部/视频/图文分类、未读提醒、标题/正文/表情/@用户及最多 9 张图片发布，
以及置顶、点赞、删除、分享链接、稍后再看；详情评论支持回复、图片、表情、赞踩和删除。
提醒通过 `/api/post/authors` 查询，`POST /api/post/read` 清除已查看用户的提醒；
置顶为 `POST /api/post/{id}/pin`；评论复用 `/api/comment`，`postId` 与 `videoId` 二选一。

创作中心保留 main 的本地/远程投稿、封面、标签、原创/转载、二创、分区、编辑、作品管理及统计界面。
分片协议为 `/api/upload/uploadVideoChunk`、`/api/upload/mergeVideoChunks` 和
`DELETE /api/upload/cleanVideoUpload`；发布/编辑为 `/api/upload/uploadVideo`、
`/api/upload/updateVideo`。身份以登录态为准，不使用表单中的用户 ID 授权。
投稿仍需审核，编辑后重新进入审核状态，不将接口修复改成自动发布。
投稿、编辑与作品管理的分区选项统一读取 product 已启用分区；不新增 main 独有的分区初始化记录。
首页频道、通用页头的探索频道、搜索分类与创作中心共用 `/api/video/categories` 的已启用分区及名称映射，顺序沿用接口返回值；首页额外保留“推荐”，搜索额外保留“全部分类”。不再显示未启用或不存在的静态分区，也不把找不到的分区静默跳转成全部视频；“番剧/国创”仅展示名映射为“动画剧场/原创动画”，查询和投稿仍使用真实 ID/名称。投稿与编辑补齐原创动画、综艺、资讯、综合的细分类及国产剧的非空选项值。
视频详情的界面调整保留现有业务规则，重点修复已有内容及控件的遮挡、截断和窄屏可见性。
弹幕列表和接下来播放区不再使用负层级、零高度隐藏，发送栏和互动栏按正常文档流排列。
详情相关收藏夹查询、播放上报、评论单条查询/置顶、弹幕撤回分别对接
`GET /api/video/{id}/folders`、`POST /api/video/{id}/play`、
`GET /api/comment/{id}`、`POST /api/comment/{id}/pin`、`DELETE /api/danmaku/{id}`。
弹幕由 `/api/video/live?videoId=...` 订阅创建/撤回事件，连接及重连时读取 HTTP 快照并合并期间的事件，
不再每 15 秒全量轮询。在线人数为当前后端实例中该视频的真实连接数（不是去重账号数，也不是跨实例人数）；
断线时显示连接状态，不用零或模拟人数替代。开发代理与生产反向代理均需支持 WebSocket Upgrade。
动态、评论及投稿从已有 @链接提取 `mentionUserIds`，由服务端验证接收者并写入通知；
不通知自己，尊重 `notify_at`，私密动态不向其他用户发通知，投稿通知仅在视频通过审核后可查询及计入未读。
视频分享使用 `GET /api/share/recipients` 选择互相关注对象，
`POST /api/video/{id}/share` 保存分享记录及可选附言，并按实际接收人数事务累计分享数；前端采用返回的真实计数。
分享记录使用现有 `private_message` 表，类型 4 表示视频分享、类型 1 表示附言；
消息页现在将类型 4 映射为视频卡片，并消费真实的会话、消息和通知数据。
上述为源码接线结果，按要求未运行测试、构建或启动服务，实际联调尚未验证。

`sql/product/01_schema.sql` 为全量初始化脚本，包含 DROP TABLE，**已有数据库不得直接执行以升级**；
已有库需按实际结构使用增量迁移，当前消息中心所需迁移见下节。此前仅写入初始化脚本的其他字段，
仍需按已有库的实际结构单独同步。新建数据库再使用更新后的初始化脚本。

### 消息中心与后台管理接口

消息中心兼容现有 `/api/privateMessage/*` 及评论通知查询地址，用户身份只取服务端登录态，
不使用请求中的 `userId`、`senderId` 授权。支持会话分页、置顶、免打扰、已读、
文字/图片发送、三分钟内撤回，以及仅对当前用户删除消息或会话；管理员删除则为全局下架。
非互相关注的普通用户在对方回复前只能发一条私信，管理员站内通知不受此限制。
图片先通过 `/api/media/image` 上传，私信仅保存上传地址，不把 Base64 图片塞入消息字段。
回复通知及视频/评论/动态点赞通知由真实互动事务写入，取消点赞会移除对应通知；
支持按栏目已读、删除和按内容屏蔽后续点赞提醒。消息设置保存到服务端，背景模式仍为本地偏好。

`/api/chat?token=...` 使用服务端验证的登录凭证建立连接，只推送该账号参与的会话变化；
消息持久化仍走 HTTP，不再相信客户端发送的 `open:用户ID` 或 `send:发送人:接收人`。
连接带心跳和断线重连，重连后读取真实数据校准；实时推送为单后端实例范围，
多实例部署仍需共享事件分发。开发代理和生产代理须允许 WebSocket Upgrade，
代理访问日志应避免记录聊天连接的完整查询串。

后台管理对接 `/api/system/*`，覆盖概览、用户/封禁、视频审核、评论/动态/私信管理、
热词和操作日志；管理员身份由当前账号的服务端角色决定，不信任表单中的 `operatorId`。
批量写操作校验目标并在事务内执行，记录操作日志，保护当前账号及最后一个管理员。
视频删除不会删除磁盘上的上传文件，存储清理需另行安排。

**已有数据库需先核对并执行一次 [03_message_state.sql](sql/product/03_message_state.sql)**，
补齐会话成员状态、消息撤回/个人删除状态、私信提醒和内容通知屏蔽表。该脚本不清空已有数据，
但不是重复执行脚本；已有同名字段或表时应先核对结构，不可盲目重跑。
新建数据库的 `01_schema.sql` 已包含这些结构，不能再叠加执行该迁移。
